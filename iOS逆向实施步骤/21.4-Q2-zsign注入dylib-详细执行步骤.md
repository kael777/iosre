# Q2 zsign 注入 dylib 实验

> 在已能 zsign 重签的前提下，用 `-l` 把自编 dylib 打进 IPA。  
> 启动 App 时 dylib 的 `constructor` 会先跑。用来验证「能加载」，不是做注册机、不是去 hook 别人的包。

zsign 会做三件事：把 dylib 拷进 `.app`、给主程序加 `LC_LOAD_DYLIB`、再整包签名。所以 **注入和重签是同一次命令**，不必先签完再单独插库。

```text
zsign -l ./lab_inject.dylib   # 可多次 -l
     -w                       # 可选：改成 LC_LOAD_WEAK_DYLIB，库缺失也不至于起不来
     -D 名字.dylib            # 从包里去掉某条注入
```

---

## 1. 编一个 arm64 实验库

`lab_inject.dylib` 是用本机 iOS SDK **现编的**，不是网上下载的。  
源码：`scripts/zsign-inject/lab_inject.m`（`constructor`：启动时 `NSLog`，并写沙盒 `Documents/zsign_lab_inject.txt`）。  
`-install_name @executable_path/lab_inject.dylib` 要和 zsign 写入主程序的 `LC_LOAD_DYLIB` 路径一致。改 `.m` 后重新跑下面的命令再 `-l`。

```bash
SDK=$(xcrun --sdk iphoneos --show-sdk-path)
OUT=~/Downloads/ll/scripts/zsign-inject/lab_inject.dylib

xcrun -sdk iphoneos clang -dynamiclib -arch arm64 \
  -isysroot "$SDK" \
  -miphoneos-version-min=13.0 \
  -framework Foundation \
  -install_name @executable_path/lab_inject.dylib \
  -o "$OUT" \
  ~/Downloads/ll/scripts/zsign-inject/lab_inject.m

file "$OUT"
```

应显示 `Mach-O 64-bit dynamically linked shared library arm64`。

## 2. 注入并重签（一次完成）

`-b` / `-m` / `-k` 与 [21.3](21.3-Q2-zsign重签安装-详细执行步骤.md) 相同，多一个 `-l`。

```bash
PROV=~/Library/Developer/Xcode/UserData/Provisioning\ Profiles/你的.mobileprovision

~/Downloads/zsign \
  -k ~/Downloads/你的.p12 \
  -p 'p12密码' \
  -m "$PROV" \
  -b 和profile一致的BundleId \
  -l ~/Downloads/ll/scripts/zsign-inject/lab_inject.dylib \
  -o ~/Downloads/ll/artifacts/resigned-inject.ipa \
  ~/Downloads/ll/artifacts/unpacked
```

日志里除了原来的 `SignFile`，还应有类似 `InjectDylib`。

## 3. 安装后怎么确认加载了

USB 装新 ipa（先删旧图标）。打开 App，然后：

```bash
# Mac 看日志
idevicesyslog | grep zsign-lab
```

或 Xcode → Devices → 该 App 容器 → `Documents/zsign_lab_inject.txt`。  
有这文件或日志，说明 constructor 已执行。

## 4. 可做的实验（本机测包）

| 实验 | 做法 | 预期 |
|---|---|---|
| A 能加载 | 上面最小库 | 有 log / txt |
| B 弱引用 | 加 `-w`，再手动从包里删掉 dylib 不重签（仅理解用） | 弱引用时缺库仍可能启动 |
| C 去掉注入 | 对已注入的 unpacked 用 `-D lab_inject.dylib` 再签 | 启动不再写 txt |
| D 换库再签 | 改 `.m` 重编，再 `-l` 打一次 | 必须整包 zsign，不能只替换未签的 dylib 去装 |

替换包内已有业务 `.dylib`：先换文件，再 **同一条** zsign（不必再 `-l`，除非还要额外注入）。见上次结论：换库 = 必须重签。

---

## 不要做的事

- 不要对商店第三方包注入去改登录/支付。  
- 不要把注入库做成注册机或改指纹去打生产。  
- 不要用 `-l` 塞来路不明的 dylib。
