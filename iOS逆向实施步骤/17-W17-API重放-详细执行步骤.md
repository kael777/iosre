# W17 API 业务逻辑与重放：详细执行步骤

> 本文件是 [`iOS逆向_2026完整实施计划.md`](../iOS逆向_2026完整实施计划.md) 中“21. W17：API 业务逻辑和重放”的执行手册。  
> **只打自己的 SignDemo 后端**（`127.0.0.1` / 局域网 IP）。  
> 对第三方/生产 API 重放、改包、探测，即使只改一个字段，也不做。

---

## 本周在练什么

M2 已经能算出合法 `sign`。W17 看 **服务端开关打开后会发生什么**，再关掉证明防护有效。

```text
正常请求 200
→ 只改 user_id（sign 仍按旧 user 算）→ 应 401
→ 只改 timestamp 过期 → 401
→ 原样重放同一 nonce → 409
→ 删掉 sign → 400
→ 改 action（login 的包拿去 order）→ 401
→ 打开缺陷开关后再看哪些会变成 200
→ 恢复安全版本
```

当前后端 **默认已有**：签名、300 秒窗口、nonce 集合。  
当前 **没有**：按 token 校验 user_id、对象级 ACL、频率限制。本周用环境变量做成可开关缺陷，而不是改死代码。

---

## 术语

| 术语 | 含义 |
|---|---|
| **重放** | 把抓到的完整请求再发一次。nonce 防的就是这个。 |
| **改包** | 只改 JSON 里某个字段。sign 不跟着改就会 401。 |
| **缺陷开关** | 仅本机开发用的 env，模拟「忘了校验」。 |
| **对象级权限** | 即使有 token，也不能拿别人的 `order_id`。W18 会加深；本周先做开关。 |
| **频率限制** | 同一 IP/用户短时间过多请求返回 429。 |

## 执行 1：安全模式基线（先测，再改后端）

后端 **不要** 加缺陷开关，和平时一样启动：

```bash
cd /Users/weideshun/Desktop/SignDemo/backend
./.venv/bin/python3 app.py
```

用现有脚本或即将写的 `replay_local_request.py`，对 **本机** `/api/login` 或 `/api/order`：

| 步骤 | 操作 | 预期 |
|---|---|---|
| A | 正常签名请求 | 200 |
| B | 只改 `user_id` 为 `demo-user-002`，sign 不重算 | 401 invalid signature |
| C | `timestamp=1` | 401 时间窗 |
| D | 成功请求原样再发一次 | 409 nonce |
| E | 去掉 `sign` 字段 | 400 missing fields |
| F | login 的 canonical/action 去打 `/api/order`（或 action 与路径不一致） | 401 |

只允许 `127.0.0.1` / 局域网。把 HTTP 状态填表。

### 验收标准

- [x] 安全模式下 A=200，B–F 均失败

## 执行 2：缺陷开关（只改自己的 app.py）

用环境变量，默认 `0`。建议名字：

```text
SIGNDEMO_DEFECT_SKIP_SIGN=0      # 1=不校验 sign
SIGNDEMO_DEFECT_SKIP_NONCE=0     # 1=不把 nonce 记入集合
SIGNDEMO_DEFECT_SKIP_WINDOW=0    # 1=不检查时间窗
SIGNDEMO_DEFECT_TRUST_USER_ID=1  # 当前本来就信客户端 user_id；1=保持，0=以后要求 token 匹配（可本周先只记录现状）
SIGNDEMO_DEFECT_SKIP_RATELIMIT=1 # 当前无频率限制；本周可先加一个简单计数，0=启用限制
```

实现原则：

- 开关只打日志：`defect skip_sign enabled`
- 不要默认打开
- 测试用完立刻设回 0
- 测试套件 `pytest` 在默认开关下仍须全绿

对象级 ACL 可本周只 **记录**：order 不看 token、只信 body 里的 user_id。完整 IDOR 放到 W18。

### 验收标准

- [x] 默认启动行为与执行 1 相同
- [x] pytest 仍通过

---

## 执行 3：每次只开一个缺陷

**一次只 export 一个 =1**，重启后端。

| 开关 | 重复哪一步 | 预期变化 |
|---|---|---|
| SKIP_SIGN=1 | E 删除 sign / B 改 user_id | 可能变成 200（演示危险） |
| SKIP_NONCE=1 | D 重放 | 第二次也 200 |
| SKIP_WINDOW=1 | C timestamp=1 | 200 |
| 其它保持 0 | A 正常请求 | 仍 200 |

每开一个就填一行「开缺陷时的 HTTP」。测完 `unset` 再开下一个。

### 验收标准

- [x] 至少三个缺陷开关各有一行对照（关=拒绝，开=放行）

---

## 执行 4：恢复

```bash
unset SIGNDEMO_DEFECT_SKIP_SIGN
unset SIGNDEMO_DEFECT_SKIP_NONCE
unset SIGNDEMO_DEFECT_SKIP_WINDOW
# 重启 app.py
```

再跑执行 1 的表，必须和第一次一样。

### 验收标准
