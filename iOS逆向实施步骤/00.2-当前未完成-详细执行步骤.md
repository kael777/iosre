## 执行 1：确认 App 标识符

### 1.1 前置条件

- XR 已通过数据线连接 Mac。
- XR 已唤醒并解锁。
- 如果 XR 刚重启，先打开 Dopamine 并重新点击 `Jailbreak`。
- Sileo 中 Frida 相关组件已安装。

### 1.2 运行命令

先执行：

```bash
frida-ps -U
```

预期能看到一批设备进程，例如 SpringBoard 等。具体进程名称会随系统状态变化，不要求和示例完全一致。

再执行：

```bash
frida-ps -Uai
```

这条命令用于列出设备上的应用，重点关注三列：

```text
PID    Name    Identifier
```

如果已经安装了目标 App，可以筛选：

```bash
frida-ps -Uai | grep -i 'sign\|uncrackable'
```

macOS 默认的 `grep` 支持这个基本表达式。如果没有结果，不要立即判断失败，先完整查看 `frida-ps -Uai` 输出。

### 1.3 记录结果

在本文件末尾的“执行记录”中填写：

```text
设备：
执行时间：
frida 版本：
目标 App 显示名称：
目标 App Bundle Identifier：
```

当前如果还没有 SignDemo，找不到 `SignDemo` 是正常的；本步骤只要求 `frida-ps -Uai` 能正常返回应用列表。

### 1.4 验收标准

- [x] XR 唤醒解锁后，`frida-ps -U` 能看到设备进程。
- [x] `frida-ps -Uai` 能返回应用列表。
- [x] 没有出现 `unable to connect to remote frida-server`。
- [x] 记录了当前 Frida 客户端版本和设备状态。

### 1.5 如果仍然没有应用列表

按这个顺序排查：

```text
确认 XR 已解锁
→ 确认数据线连接
→ 确认 Finder 能看到 XR
→ 确认 Dopamine 已重新激活
→ 再执行 frida-ps -U
→ 最后再执行 frida-ps -Uai
```

如果 `frida-ps -U` 有进程、`frida-ps -Uai` 没有应用，先把完整输出保存下来，不要重装工具。此时可能只是应用枚举或终端输出问题。

## 执行 2：创建 SignDemo 并完成第一次 Frida attach/spawn

### 2.1 在 Xcode 创建工程

打开 Xcode，选择：

```text
File → New → Project
```

选择：

```text
iOS → App
```

填写：

```text
Product Name: SignDemo
Team: 选择登录的 Apple Account
Organization Identifier: com.weideshun
Bundle Identifier: com.weideshun.SignDemo
Interface: Storyboard
Language: Objective-C
```

如果当前 Xcode 模板没有 `Storyboard` 选项，选择可用的 UIKit 模板。关键目标是先生成一个能在真机运行的 App；后续 Hook 会以工程实际类名为准。

将工程保存到：

```text
/Users/weideshun/Desktop/SignDemo/SignDemo
```

不要保存到 iCloud 同步目录、临时下载目录或带大量空格的路径。

### 2.2 配置免费签名

在左侧 Project Navigator 点击蓝色工程图标，然后在 TARGETS 中选择 `SignDemo`：

1. 打开 `Signing & Capabilities`。
2. 勾选 `Automatically manage signing`。
3. `Team` 选择自己的 `Personal Team`。
4. 确认 Bundle Identifier 是：

```text
com.weideshun.SignDemo
```

如果 Xcode 报 Bundle Identifier 已被占用，改为自己的唯一值，例如：

```text
com.weideshun.iosreverse.signdemo
```

后续所有 Frida 命令都必须使用 Xcode 实际显示的值。

### 2.3 连接 XR 并首次运行

1. 用数据线连接 XR。
2. XR 解锁并点击“信任此电脑”。
3. 确认开发者模式已打开：

```text
设置 → 隐私与安全性 → 开发者模式
```

4. Xcode 顶部运行目标选择 XR。
5. 不要选择任何 `iPhone Simulator`。
6. 点击 `Run`，或按 `Command + R`。

首次运行可能出现：

- `Register Device`：允许 Xcode 注册设备。
- `Set Up Signing`：允许 Xcode 设置签名。
- 手机提示不信任开发者：到“VPN 与设备管理”中信任对应开发者 App。

### 2.4 确认 App 已安装

App 成功启动后，在终端执行：

```bash
frida-ps -Uai | grep -i 'signdemo'
```

如果 Bundle Identifier 已改成其他值，使用实际值筛选：

```bash
frida-ps -Uai | grep -i 'iosreverse'
```

也可以不筛选，直接查看完整列表：

```bash
frida-ps -Uai
```

### 2.5 第一次 spawn

将 `<bundle-id>` 替换成真实 Bundle Identifier：

```bash
frida -U -f <bundle-id>
```

例如：

```bash
frida -U -f com.weideshun.SignDemo
```

预期结果：

- Frida 进入交互控制台。
- SignDemo 被启动或重新启动。
- 没有 `Failed to spawn`。

退出控制台：

```text
输入 %exit
```

### 2.5.1 如果出现 `FBSApplicationLibrary returned nil`

典型错误：

```text
Failed to spawn: unable to launch iOS app via FBS:
Application info provider (FBSApplicationLibrary) returned nil for "com.example.app"
```

含义：Frida 已经连接到 XR，但 iOS 找不到这个 Bundle Identifier 对应的已安装 App。常见原因：

- SignDemo 还没有通过 Xcode 安装到 XR。
- Xcode 中实际 Bundle Identifier 不是命令里填写的值。
- App 已经被删除或安装失败。
- XR 锁屏，导致应用枚举结果不完整。
- 把 SignDemo 的 Bundle Identifier 用在了 UnCrackable，或反过来。

按下面顺序处理：

1. 唤醒 XR、解锁，并停留在主屏幕。
2. 查看设备上的应用列表：

```bash
frida-ps -Uai
```

3. 筛选可能的目标：

```bash
frida-ps -Uai | grep -i 'sign\|demo\|uncrackable'
```

4. 使用输出中 `Identifier` 列的**实际值**重新执行：

```bash
frida -U -f <实际Bundle-Identifier>
```

5. 如果列表中没有 SignDemo，回到 Xcode：

```text
打开 SignDemo 工程
→ TARGETS → SignDemo → General → Identity
→ 查看 Bundle Identifier
→ Signing & Capabilities 确认 Team 和自动签名
→ 运行目标选择 XR
→ Command + R 安装并启动
```

6. App 在 XR 上启动后，再次执行 `frida-ps -Uai`。

注意：当前命令：

```bash
frida -U -f com.weideshun.SignDemo
```

只会启动已经安装且 Bundle Identifier 正好为 `com.weideshun.SignDemo` 的 SignDemo。Bundle Identifier 必须严格复制 Xcode 或 `frida-ps -Uai` 输出的值，大小写不要自行修改。它不会启动当前目录里的 Xcode 工程，也不会启动 UnCrackable。

### 2.6 第一次 attach

先手动打开 SignDemo，再执行：

```bash
frida -U -n SignDemo
```

如果显示名称不是 `SignDemo`，使用 `frida-ps -Uai` 输出中的实际名称：

```bash
frida -U -n '<实际显示名称>'
```

也可以按 PID attach：

```bash
frida -U -p <PID>
```

### 2.7 验收标准

- [x] SignDemo 能在 XR 上启动。
- [x] `frida-ps -Uai` 能看到 SignDemo。
- [x] `frida -U -f <bundle-id>` 成功。
- [x] 能对运行中的 SignDemo 执行 attach。
- [x] 记录实际 Bundle Identifier。

## 执行 3：建立本地后端、签名协议和测试数据

### 3.1 建立目录

在工作目录执行：

```bash
mkdir -p SignDemo/backend/tests
mkdir -p SignDemo/scripts
```

后端第一阶段建议使用 Flask，依赖少、便于观察请求。检查 Python：

```bash
python3 --version
```

创建虚拟环境：

```bash
cd SignDemo/backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install flask
```

### 3.2 第一阶段后端功能

后端需要实现三个接口：

```text
GET  /api/health
POST /api/login
POST /api/order
```

第一阶段先使用 HTTP，不加 HTTPS 和 Pinning。这样可以先确认：

```text
App 是否能访问后端
→ 参数是否正确
→ 签名是否正确
→ mitmproxy 是否能看到请求
```

### 3.3 固定测试数据

只使用虚构数据：

```text
user_id: demo-user-001
password: demo-password
order_id: order-001
```

第一阶段的测试 secret 可以写在本地配置中：

```text
secret: local-demo-secret-v1
```

不要使用自己的真实密码、真实 Token 或任何第三方服务凭据。

### 3.4 签名规则

对登录和订单请求使用同一套可解释规则：

```text
canonical =
    user_id=<user_id>
    &timestamp=<timestamp>
    &nonce=<nonce>
    &action=<action>
```

签名：

```text
sign = HMAC-SHA256(secret, canonical)
```

规则必须固定：

- 参数顺序固定。
- 字符串使用 UTF-8。
- 输出使用小写十六进制。
- 时间戳允许前后 300 秒。
- nonce 先记录在内存集合中，后续再改为持久化。

### 3.5 后端启动和本机验证

后端监听局域网地址，方便 XR 访问：

```bash
flask --app app run --host 0.0.0.0 --port 5000
```

Mac 本机验证：

```bash
curl http://127.0.0.1:5000/api/health
```

预期返回 JSON，例如：

```json
{"ok":true,"service":"SignDemo"}
```

查看 Mac 局域网 IP：

```bash
ipconfig getifaddr en0
```

如果 Mac 当前使用其他网络接口，使用系统实际分配的局域网 IP。

### 3.6 App 接入 health

把 SignDemo 的后端地址设置为：

```text
http://<Mac局域网IP>:5000
```

例如：

```text
http://192.168.1.20:5000
```

不要在真机 App 中使用 `127.0.0.1`，因为那代表 XR 自己，而不是 Mac。

如果 iOS 阻止 HTTP 请求，需要在练习 App 的 `Info.plist` 中为本地实验临时配置 ATS 例外。只对自建开发 App 使用，实验结束后删除例外并恢复 HTTPS。

### 3.7 App 接入 login 和 order

请求 JSON 至少包含：

```json
{
  "user_id": "demo-user-001",
  "timestamp": 1730000000,
  "nonce": "random-test-nonce",
  "sign": "calculated-hmac",
  "password": "demo-password"
}
```

订单请求额外包含：

```json
{
  "order_id": "order-001",
  "amount": 10
}
```

App 页面至少提供：

- `Health` 按钮。
- `Login` 按钮。
- `Create Test Order` 按钮。
- 一个显示 HTTP 状态码和响应正文的文本区域。

### 3.8 后端验收

至少验证以下情况：

| 测试 | 预期 |
|---|---|
| 正常 health | 200 |
| 正确签名 login | 200 |
| 修改一个字段但不改 sign | 401 或 403 |
| timestamp 超时 | 401 或 403 |
| 相同 nonce 第二次使用 | 409 或 403 |
| 正常 order | 200 |

### 3.9 产物

- `SignDemo/backend/app.py`
- `SignDemo/backend/requirements.txt`
- `SignDemo/backend/README.md`
- `SignDemo/scripts/sign_local_request.py`
- `notes/week-03-frida.md`

## 执行 5：完成 UnCrackable L1 静态定位和动态分析

### 5.1 目标

这一步不是马上“破解一个陌生 App”，而是建立一条可解释的分析链：

```text
阅读源码
→ 找到 root/调试/密钥校验代码
→ 运行 App 观察行为
→ 用 Frida 观察方法是否执行
→ 记录成功/失败分支
```

### 5.2 静态阅读顺序

在 Xcode 工程中先搜索这些关键词：

```text
jailbreak
root
debug
secret
key
pass
verify
alert
```

记录：

- 类名。
- 方法名。
- 字符串常量。
- 条件分支。
- 触发失败提示的位置。
- 进入成功逻辑的条件。

不要先根据网上现成脚本猜方法名；先以当前源码和编译产物为准。

### 5.3 运行观察

打开源码版 App，分别记录：

1. 正常启动时是否出现越狱提示。
2. 输入错误值时的提示。
3. 输入正确值时的行为。
4. App 是否因为检测结果退出或阻止继续。

### 5.4 Frida 观察脚本

第一阶段只做观察：

- 打印目标方法是否被调用。
- 打印安全的字符串参数。
- 打印返回值。
- 不读取未知指针。
- 不批量 Hook 所有系统函数。

运行形式：

```bash
frida -U -f <实际bundle-id> -l scripts/frida/uncrackable_l1_observe.js
```

如果尚未建立脚本目录：

```bash
mkdir -p scripts/frida
```

脚本目标应来自你在 Xcode 源码中确认过的方法，不要直接照抄其他版本的类名。

### 5.5 动态记录模板

```text
目标方法：
所在类：
触发动作：
进入次数：
参数：
返回值：
UI 结果：
是否与源码判断一致：
```

### 5.6 验收标准

- [x] 能说明至少一个 root/调试检测点。
- [x] 能说明密钥或口令校验从输入到分支的路径。
- [x] Frida 能证明目标方法确实执行。
- [x] 静态源码、运行行为和 Frida 输出相互对应。
- [x] 分析对象是自己编译安装的授权靶场版本。

## 执行 6：完成第一份 SignDemo 抓包分析报告

### 6.1 前置条件

### 6.3 再抓 login 和 order

- `user_id`。
- `timestamp`。
- `nonce`。
- `sign`。
- Token 或 Cookie。
- 服务端错误信息。

脱敏规则：

- 不把真实密码写入报告。
- 不把设备唯一标识写入公开笔记。
- 测试 Token 可以保留，但要标注为本地虚构数据。
