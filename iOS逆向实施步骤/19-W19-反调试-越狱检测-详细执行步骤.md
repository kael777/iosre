# W19 反调试、越狱检测与反分析：详细执行步骤

> 本文件是 [`iOS逆向_2026完整实施计划.md`](../iOS逆向_2026完整实施计划.md) 中“23. W19：反调试、越狱检测和反分析”的执行手册。  
> 对象：**自己的 SignDemo** + 自己的 XR（Dopamine rootless）。  
> 不要对商店 App 做越狱检测绕过，不要把「Hook 返回 NO」当成安全性结论。

---

## 本周在练什么

W6 已经有可开关的 `AntiDebug`（`sysctl` 看 `P_TRACED`，命中只打日志，**不 exit**）。W19 把检测面补全，并证明：**客户端说「安全」替代不了服务端授权**（W17 / W18）。

```text
先看现有反调试（明文、不杀进程）
→ 加三类越狱检测（路径 / URL Scheme / 动态库与环境变量）
→ Frida 只观察检测点
→ 记下误报和漏报（Dopamine rootless ≠ 网上 Cydia 教程）
→ 路径字符串做简单 XOR 混淆，再定位一次
→ 比较成本和收益
```

绕过成功只说明 **这段客户端逻辑可被改**。登录、下单、读别人订单仍由后端 HMAC + ACL 管。

---

## 术语

| 术语 | 含义 |
|---|---|
| **反调试** | 运行时判断「现在有没有调试器」。常见：`sysctl` 的 `P_TRACED`、`ptrace(PT_DENY_ATTACH)`。 |
| **代码签名** | 谁签了这份二进制（免费开发证书 / 商店 FairPlay）。和「有没有调试器」不是一层。 |
| **越狱检测** | 判断环境是否被改过：异常文件、可打开的越狱 URL、注入的 dylib。 |
| **rootless** | Dopamine 把越狱文件放在 `/var/jb` 等前缀下，**不是** `/Applications/Cydia.app`。 |
| **误报 FP** | 没越狱/没调试，检测却说有。 |
| **漏报 FN** | 已经越狱/已注入，检测却说没有。 |
| **检测面** | 一类检查思路。本周至少三类：文件路径、URL Scheme、动态库/环境变量。 |

三层不要混：

| 层 | 管什么 | 挡不住什么 |
|---|---|---|
| 代码签名 | 安装来源、是否被重签 | 越狱后 Frida attach 自己的 Debug 包 |
| 反调试 | 当前是否被 trace | 不 attach 调试器、只改 API 参数 |
| 越狱检测 | 设备环境 | Hook 检测函数让它返回「没越狱」 |

## 执行 1：现有反调试（不改逻辑）

反调试开关先打开，分别看三种启动：

| 启动方式 | 预期（记实际，不要抄） |
|---|---|
| 主屏幕点图标 | 通常 `P_TRACED=NO`，业务仍可用 |
| Xcode `Command + R` | 常出现 `P_TRACED=YES`（调试器已连上） |
| `frida -U -f com.weideshun.SignDemo` 或 attach | 可能 `P_TRACED` 和/或 `isatty` |

把界面上的 `P_TRACED=` / `getppid=` / `isatty=` 抄进执行记录。进程 **必须还在**，Login 仍能点。

本周 **不要** 默认打开 `ptrace(PT_DENY_ATTACH)`。它会让后续 Frida / Xcode 挂不上，挡执行 3。读懂它和 `sysctl` 是同一层（反调试），和 `codesign` / `cryptid`（W9）不是一层即可。

用自己的话写两句：

1. 免费开发证书能装 App，**不能** 说明「没被调试」。
2. `P_TRACED=YES` **不能** 说明「签名坏了」。

### 验收标准

- [ ] 三种启动至少记了两行 `statusSummary`
- [ ] 能口头区分反调试和代码签名

## 执行 2：明文三类检测（只改自己的 SignDemo）

新建 `JailbreakCheck`，点按钮或开关时打印结果。规则与 W6 反调试相同：**只检测、只打日志，不 exit、不禁用 Login**。

至少三类：

### 2.1 文件路径

同时查 **网上常见路径** 和 **Dopamine rootless**，用来制造漏报对照：

```text
常见（在这台 XR 上很可能不存在 → 漏报）
  /Applications/Cydia.app
  /Library/MobileSubstrate/MobileSubstrate.dylib

rootless（更可能存在 → 命中）
  /var/jb
  /var/jb/usr/sbin/sshd
  /var/jb/Applications/Sileo.app
```

用 `NSFileManager fileExistsAtPath:`。路径先写明文，方便 `strings` 搜到。

### 2.2 URL Scheme

`Info.plist` 增加 `LSApplicationQueriesSchemes`：`cydia`、`sileo`、`filza`。  
`canOpenURL:` 查 `cydia://`、`sileo://`、`filza://`。

不登记的 scheme 在新系统上会一直 `NO`，那是 API 限制，不是「没装 Sileo」。

### 2.3 动态库 / 环境变量

- `getenv("DYLD_INSERT_LIBRARIES")`
- `_dyld_get_image_name` 扫一遍，看是否出现 `frida`、`TweakInject`、`ellekit`、`substrate`（大小写不敏感）

Frida **没 attach** 时，镜像列表里往往没有 `frida`；attach 后再查才可能命中。这是漏报点，要记。

界面输出建议一行一类：

```text
file: Cydia=NO /var/jb=YES Sileo.app=…
scheme: cydia=NO sileo=YES filza=…
image: DYLD_INSERT=… frida=NO ellekit=…
```

Xcode 编到 XR。不要卸 SignDemo 去装别的检测 App（免费账号 3 App 上限）。

### 验收标准

- [ ] 三类都有输出
- [ ] Login / Health 仍可用
- [ ] `strings` 能搜到 `/var/jb` 或 `Cydia`

## 执行 3：Frida 观察 + 误报漏报表

脚本：`scripts/frida/observe_jailbreak_checks.js`

只 hook、只打印，**不要** `replace` 成「没越狱」。Frida 17 不要 `Module.findExportByName`。

建议观察：

- `+[JailbreakCheck …]` 各类结果
- `+[AntiDebug isBeingTraced]` / `statusSummary`
- `-[NSFileManager fileExistsAtPath:]`（可过滤 path 含 `jb` / `Cydia` / `Sileo`）
- `-[UIApplication canOpenURL:]`

```bash
# 先让 XR 解锁、停在主屏幕
frida -U -f com.weideshun.SignDemo -l scripts/frida/observe_jailbreak_checks.js
```

点检测按钮，把命中的 path / scheme 记下来。

填表（按 **这台 Dopamine XR** 的实际，不要抄网上 Cydia 文章）：

| 检测 | 未注入 Frida | Frida attach 后 | 判定 |
|---|---|---|---|
| `/Applications/Cydia.app` | | | 多半漏报 |
| `/var/jb` | | | |
| `sileo://` | | | |
| `cydia://` | | | |
| 镜像名含 `frida` | | | 未 attach 时常漏报 |
| `P_TRACED` | | | 反调试，不是越狱 |

误报例子：把 `getppid != 1` 当成越狱（W6 已排除，越狱后父进程经常不是 1）。  
漏报例子：只查 Cydia 路径，Dopamine 上全 NO。

### 验收标准

- [ ] 脚本只读，进程没被脚本杀掉
- [ ] 表里至少三类检测面，且标明 FP 或 FN

## 执行 4：简单混淆后再定位

把 **路径字符串** 做成和 `SecretStore` 类似的 XOR（例如 0x5A），运行时还原再 `fileExistsAtPath:`。

- Scheme 名、`frida` 子串也可以拆，但本周 **至少路径** 从明文消失
- 方法名可以仍叫 `JailbreakCheck`，报告里写：混淆的是字面量，不是算法
- **不要** 为了「更强」去 `ptrace` + `exit`

对照：

```bash
strings SignDemo.app/SignDemo | grep -E 'Cydia|/var/jb|sileo'
```

| | 混淆前 | 混淆后 |
|---|---|---|
| `strings` 里 `/var/jb` | 有 | 应没有或很难直接 grep |
| 运行时 `/var/jb` 检测 | 命中 | 仍应命中（只是存放变了） |
| Frida hook `fileExistsAtPath:` | 能看到明文 path | 仍能看到还原后的 path |

结论写进报告：混淆提高静态搜索成本，**不提高** 对 Frida 的抵抗。攻击者 hook 的是 `fileExistsAtPath:` 或整个 `+check`，不需要把字符串搜出来。

### 验收标准

- [ ] 混淆后 `strings` 不再直接出现 `/var/jb`
- [ ] 运行时检测结果与执行 2 同类（该 YES 的仍 YES）
- [ ] Frida 仍能在 hook 里看到还原后的路径

## 不要做的事

- 不要默认 `exit()` / `ptrace(PT_DENY_ATTACH)`。
- 不要对第三方 App 做越狱检测绕过或去特征。
- 不要把 Frida 脚本写成全局 SSL Kill。
- 不要安装「隐藏越狱」插件来当作业。
- 不要为了检测去卸 SignDemo 换 DVIA（3 App 上限）；DVIA 的 Jailbreak Detection 菜单最多对照，不当本周主路径。
- 不要宣称绕过客户端检测等于拿到生产数据。
