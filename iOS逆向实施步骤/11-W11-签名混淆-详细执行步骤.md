## 本周在练什么

现在 secret 是明文：

```objc
NSString * const SignDemoSigningSecret = @"local-demo-secret-v1";
```

`strings` 一眼就能看到。W11 要把它变成 **简单混淆**（拆成多段 + 固定字节变换），让静态搜索变难，但运行时仍还原成 **同一串**，后端继续接受。

```text
抓一组已知输入输出（改造前）
→ 改 App：拆分 + XOR，保留 Debug 开关
→ Hook HMAC 的 key / message / digest
→ Ghidra 搜常量和还原函数
→ Python 按同样规则还原 secret 并算出相同 sign
```

**不是** 换 HMAC 算法，也不是改 canonical。改完 Login 仍须 200。

不要上白盒、AES 包一层、或 JNI 级保护。那不是本周。

## 执行 2：改 App（简单混淆）

### 2.1 规则（按这个做，方便 Python 复现）

最终运行时 secret 仍必须是：

```text
local-demo-secret-v1
```

建议实现（可微调，但要写进笔记）：

```text
明文按 UTF-8
拆成两段字节：
  partA = 前 10 字节
  partB = 其余字节
每字节 XOR 0x5A
App 里只存 XOR 后的十六进制或 C 数组，不要再写整串 @"local-demo-secret-v1"（开关关闭时）

还原：
  把两段 XOR 0x5A 再拼回去，得到 NSString
```

新类例如 `SecretStore`：

```objc
+ (NSString *)obfuscatedSecret;
+ (NSString *)plainSecret;      // 仅开关打开时用，或 Debug 才链进去
+ (NSString *)currentSecret;    // 看开关
```

`APIClient` 签名时用 `[SecretStore currentSecret]`，不要到处抄常量。

### 2.2 Debug 开关

页面加 **明文 secret** 开关，默认 **关**。

| 开关 | 行为 |
|---|---|
| 关 | 走拆分 + XOR 还原 |
| 开 | 走原来的 `SignDemoSigningSecret` 字面量，方便和旧版对比 |

两种路径算出的 sign **必须相同**（都还原/使用同一明文）。开开关只是让 `strings` 更容易再看到旧常量。

不要把 XOR 密钥做成随机、不要加网络下发。

### 2.3 不要改的

- canonical 格式
- HMAC-SHA256
- 后端 `SIGNDEMO_SECRET`
- Pinning / 反调试默认值

### 2.4 验收标准

- [x] 开关关闭时代码路径不依赖那一整串字面量参与运算（运算来自还原）
- [x] `HMACSigner` 仍只做 HMAC，不负责混淆

## 执行 6：Python 复现

```text
/Users/weideshun/Desktop/SignDemo/scripts/reproduce/sign_v2.py
```

必须：

1. 按 App 同样规则 XOR + 拼接得到 secret
2. 再用旧 canonical + HMAC-SHA256
3. 对同一组 timestamp/nonce，sign 与 Frida 抓到的一致
4. 请求自己的后端 Login 得 200

不要把还原逻辑写成「直接写死明文」却假装混淆；明文只作为断言：

```text
assert secret == "local-demo-secret-v1"
```

只允许打 `127.0.0.1` / 局域网。
