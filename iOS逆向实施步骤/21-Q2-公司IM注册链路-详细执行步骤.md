# Q2 公司 IM 注册链路：详细执行方案

> 外层计划：[`iOS逆向_2026Q2完整实施计划.md`](../iOS逆向_2026Q2完整实施计划.md)  
> 对象：**本公司 IM 测试包**（工作名 `myim.ipa`）+ **测试服** + **测试号**  
> 目的：搞清注册机为什么能过——多半是协议和「只信客户端指纹」，不是把加固二进制翻完。  
> **不写注册机、不接接码打生产、不碰 WhatsApp。**

---

## 这套方案在干什么

Q1 SignDemo 已经证明：改 `user_id`、重放、XOR、越狱检测，**服务端不验就会过，验了就不过**。  
Q2 把同一套问题问你们 IM 的 **注册**：

```text
测包能不能分析（cryptid）
→ 注册四步的 host / 路径 / 字段
→ 指纹在哪个字段、怎么生成
→ 只改指纹，测试服是否仍注册成功
→ 验证码能否重放
→ 哪些该改服务端（DeviceCheck、一码一号、限速）
```

对应计划里的 **M4 → M5 → M6**。Q2-W8 之后的加固对照、复盘仍按外层 12 周走；**本文件是开干用的清单**。

---

## 不要做的事

- 不要实现或分发注册机。
- 不要用接码平台打生产库、不要刷真实用户。
- 不要把商店第三方 IM 当对照实验。
- 不要把 `*.ipa`、真手机号、生产 Token 提交进 git（已 gitignore `*.ipa`）。
- 不要默认全局 SSL Kill；测试包钉扎挡 mitm 时，优先要一份关钉扎的测包。
- 业务是否成功看 **JSON / 是否真正落户**，不要只看 HTTP 200。

## 执行 1：授权、测包、cryptid（M4 前半）

公司侧先写清（可贴进笔记，不要贴进公开 git 的真名也可以用「测试服 A」）：

```text
授权人：
测试 API 根地址：
测试号（1～2 个）：
允许：观察注册流量、改自己的测试号指纹字段
禁止：生产库、真实用户短信、外发注册脚本
```

包优先顺序：

1. Xcode / 企业签的 **Debug、Ad-hoc、测包**（多为 `cryptid=0`）
2. 才是商店 IPA（常 `cryptid=1`，FairPlay 未解前 Ghidra 看不到业务码）

把 IPA 放在 **不要提交** 的目录，例如 `~/Downloads/ll/artifacts/myim/`（`artifacts/` 已 gitignore）。

```bash
IPA=~/Downloads/ll/artifacts/myim/myim.ipa
DEST=~/Downloads/ll/artifacts/myim/unpacked
rm -rf "$DEST" && mkdir -p "$DEST" && unzip -q "$IPA" -d "$DEST"
APP=$(find "$DEST/Payload" -name '*.app' -maxdepth 1 | head -1)
BIN="$APP/$(/usr/libexec/PlistBuddy -c 'Print :CFBundleExecutable' "$APP/Info.plist")"
echo "app=$APP"
echo "bin=$BIN"
/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "$APP/Info.plist"
otool -l "$BIN" | grep -A2 cryptid
```

记下：

| 项 | 值 |
|---|---|
| Bundle ID | |
| 版本 / 构建号 | |
| cryptid | 0=可静态看；1=先换测包 |

`cryptid=1` 时 **本周不要硬脱壳当主路径**，回头要公司再打一份未加密测包。

产物：`notes/q2-week-01-ipa.md`（可只写 Bundle ID 和 cryptid，不要写测试号明文也可以写「号 A」）。

### 验收标准

- [ ] 授权范围书面化（至少你自己能说清）
- [ ] Bundle ID + cryptid 已记录
- [ ] ipa 不在 git 里

## 执行 2：装上 XR，确认进程（M4 后半）

免费账号 **3 个 App**。XR 上若已有 SignDemo / InsecureApp / UnCrackable，装不下就先卸一个练习包（可卸 UnCrackable）。

装好后 XR 解锁、USB：

```bash
frida-ps -Uai | grep -i -E 'im|myim'   # 按实际 Bundle 名改
frida-ps -U | head
```

能看到进程即可。若一点开就闪退：先记现象，不要本步对抗反调试。

### 验收标准

- [ ] `frida-ps` 能列出 IM 进程
- [ ] App 能停在注册/登录页

## 执行 3：走一遍注册，画出四步（M5）

用 **测试号** 在测试服走完一次（能验证码就提交，不要用生产号）。

能抓到 HTTPS 最好（测试包关钉扎，或公司提供不钉扎构建）。抓不到就先在 Mac 用公司测试环境的日志 / Charles 对公司测试域名，**只记自己的请求**。

按实际接口改名字，表格必须填满：

| 步 | 你在界面上点的 | 方法 | host | 路径 | 请求里像指纹的字段 | 像签名/token 的字段 | 怎样算业务成功 |
|---|---|---|---|---|---|---|---|
| 1 取号/发短信 | | | | | | | |
| 2 提交验证码 | | | | | | | |
| 3 落户/登录 | | | | | | | |
| 4 进 IM（可选） | | | | | | | |

「像指纹」：`deviceId`、`uuid`、`idfv`、`oaid`、`did`、`device_token`、一长串 hex。  
「像签名」：`sign`、`sig`、`mac`、`token`。

产物草稿：`reports/myim-register-traffic.md`（可先只有表，host 可脱敏成 `api.test.example`）。

### 验收标准

- [ ] 至少前三步有路径和关键字段名
- [ ] 写清「成功」看哪个业务字段，不是只写 200

## 执行 4：指纹从哪来（生成点）

对照 Q1 W7：运行时优先于 `strings`。

目标：执行 3 表里那个指纹字段，是

- `identifierForVendor`
- Keychain 里存的 UUID
- 自己拼的（机型 + 版本 + 随机数）
- 还是服务端下发再回传

Frida **只打印、不改返回值**（脚本以后再收；本步用手工 hook 或现有观察脚本改类名）。

记下：

```text
字段名：
第一次启动：
删 App 重装：
hook 该 getter 时上报值是否变：
```

若加固导致一时找不到 getter：仍以 **请求体里的字段名** 为准，执行 5 直接改包。

### 验收标准

- [ ] 能指出指纹是「客户端上报」还是「Apple/服务端证明」
- [ ] 客户端上报 → 执行 5 必做改包

## 执行 5：只改指纹，看还能不能过（M6 核心）

只打 **测试服**、**测试号**。一次只改指纹，其它（验证码、时间戳）保持合法。

| 编号 | 操作 | 业务结果（落户/失败原因） |
|---|---|---|
| A | 正常走完注册 | |
| B | 同一验证码流程，只把指纹字段改成另一串 | |
| C | （可选）Frida hook getter，界面再走一遍 | |

你已经感觉「能改」。本步要变成表：B 若仍成功，结论就是 **服务端没把指纹当可信设备证明**，注册机换串即可当新设备。

不要为此去接码刷号。两个测试号、改字段即可。

产物：`reports/myim-fingerprint.md`

### 验收标准

- [ ] A/B 都有业务结果（成功或明确错误码）
- [ ] 若 B 成功，报告写明「只信客户端」

## 执行 6：验证码重放一行 + 防御建议

对照 Q1 W17，只做最小集（测试号）：

| 编号 | 操作 | 预期（防御够时） | 实际 |
|---|---|---|---|
| D | 验证码提交成功后再原样重放 | 拒绝 | |
| E | 过期后再提交 | 拒绝 | |

然后写 `reports/myim-register-defense.md` 草稿，只允许这类建议：

- 短信：一码一号、短时窗、同一号段/IP 限速
- 指纹：不能当唯一门槛；iOS 用 DeviceCheck / App Attest
- 同一指纹短时间对多个号成功 → 拒绝
- 客户端加固（混淆、越狱检测、XOR）**不能**单独用来解释「为什么还有注册机」

### 验收标准

- [ ] D 或 E 至少一行实测
- [ ] 防御稿区分「客户端难看」和「服务端可拦」
